# 个人作品与 AI 工作流网站设计规格

日期：2026-08-23
状态：已完成访谈与视觉方向确认，待用户审阅书面规格

## 1. 项目目标

建设一个持续更新的个人品牌型简历网站。首要目标是让潜在客户了解作者具备 AI 内容与设计工作流搭建能力，并愿意通过微信或邮箱联系；次要目标是让招聘方或合作伙伴快速判断作者的视觉基础、项目经验和当前方向。

网站不是服务报价页、教程站或单纯作品仓库。它应在 1 至 2 分钟内说明：作者是谁、做过什么、现在擅长什么、正在研究什么，以及如何联系。

## 2. 定位与叙事

核心身份：有传统视觉设计基础、正在把 AI 变成实际生产系统的工作流实践者。

内容优先级：

1. AI 工作流搭建
2. AI 视觉在真实场景中的应用
3. 传统 PS 设计作品作为视觉基础证明
4. 当前状态、短灵感与少量长文章
5. 筛选后的经历、核心工具与联系方式

传统作品不承担主叙事，只证明视觉基本功。AI 视觉以海报、电商、自媒体等实际应用为主，以风格探索为辅。

目前已有约 5 个成熟工作流案例，这是首批上线内容而非固定栏目数量。网站结构必须为后续新增的工作流、AI 应用案例及其他项目类型保留扩展位置。

## 3. 第一版范围

第一版包含：

- 响应式首页
- 可扩展的工作流列表、归档和详情页
- 可分类筛选的视觉作品库
- 图片灯箱和少量代表项目详情页
- 短灵感列表和文章详情页
- 首页内的个人简介、当前状态、核心工具、微信二维码和邮箱
- GitHub Pages 自动构建与发布
- 基础 SEO、无障碍和移动端适配

第一版不包含：

- 登录或内容管理后台
- 访问统计或行为追踪
- 搜索、评论、点赞、订阅
- 联系表单
- 社交平台外链
- PDF 简历下载
- 完整英文版
- 价格、服务套餐和强销售区块

## 4. 信息架构

### 4.1 首页

首页是一份快速个人简历，也是各类案例的入口。顺序为：

1. 身份定位、当前状态和首屏动态视觉
2. 重点 AI 工作流（从全部案例中选取部分展示）
3. AI 视觉应用精选
4. 传统设计基础精选
5. 最新短灵感与文章
6. 关于我、经历与核心工具
7. 微信二维码、邮箱和简短合作提示

“关于我”和“联系”不设置独立页面，导航入口滚动到首页对应位置。其他页面只保留精简的全站联系页脚，不重复完整个人介绍。

### 4.2 工作流

工作流首批约 5 个，数量不固定且不设上限。每项内容包含名称、用途、简介、封面或截图、年份、排序、状态和是否精选，可选详情内容与版本关系。新增工作流只需增加内容文件和图片，不需要修改页面结构。

状态包括：

- `active`：当前每天或经常使用
- `evolving`：仍在持续优化
- `archived`：已过时或停止使用

`featured` 作为独立布尔字段控制是否出现在首页精选区，因此不会与使用状态冲突。普通旧版进入归档；有价值的重要迭代可保留版本过程。普通项目使用图片和简短说明，代表项目拥有独立详情页。

### 4.3 视觉作品

初始内容约 60 张，分类至少包括海报、电商主图、自媒体封面、活动排版、节日热点图和 AI 场景图。分类可继续增加。

功能包括：

- 无刷新分类筛选
- 图片懒加载与响应式尺寸
- 点击放大查看
- 名称、年份、类别和一句说明
- 少量代表项目进入独立详情页

只发布网页压缩版，不加水印，不上传 PSD、源文件或印刷级原图。

### 4.4 思考

同时支持短灵感和完整文章。第一版上线前准备一篇文章与 3 至 5 条短灵感；没有内容时不显示空栏目。

首篇文章由作者提供真实经历和零散想法，再协助整理。文字应保留个人语气，不写成模板化 AI 文案。

## 5. 视觉系统

方向名称：暖色未来编辑风。

设计由艺术画册的排版秩序、AI 工作流的流动感和个人创作档案气质组成。Mondragon Demo 1 仅作为视觉参考，不复制其品牌、代码、图片、字体或专属组件。

### 5.1 色彩

- 暖米色背景：约 `#EDE6D8`
- 深咖啡文字：约 `#241B16`
- 浓咖啡区块：约 `#30231D`
- 陶土强调色：约 `#A85F3B`
- 沙金粒子：约 `#C6A36A`
- 少量灰绿色：约 `#72745E`

最终色值需在真实作品导入后进行对比度和综合色彩校准。

### 5.2 排版与构图

- 超大粗体章节标题与极小编号、年份、状态文字形成尺度反差
- 中文为主要阅读语言，英文用于导航、章节词和视觉辅助
- 作品采用不规则比例、局部裁切和编辑式网格
- 使用大量有效留白，不堆叠统一圆角卡片
- 中文字体优先使用有合法网页授权的开源字体，并提供稳定回退字体

### 5.3 动效

首屏使用原创“工作流场”：细小粒子、连线、图片碎片与文字节点缓慢聚合和流动。它表达不断生长的工作系统，不使用机器人、芯片或蓝紫霓虹。

动效规则：

- 约 80% 静态、20% 动态
- 粒子以长周期缓慢循环，鼠标靠近时只产生轻微偏移
- 标题和图片在进入视口时分层显现
- 作品悬停时轻微位移并显示信息
- 分类切换时平滑重排
- 米色内容区与深咖联系区以少量粒子过渡
- 手机端减少粒子数量或使用预渲染循环动画
- 遵守 `prefers-reduced-motion`，必要时完全静止

## 6. 技术架构

第一版使用 Astro 构建静态网站。原因是内容可通过结构化数据与 Markdown 管理，并在构建阶段生成独立详情页，适合 GitHub Pages 托管和未来扩展。

内容集合包括：

- `workflows`
- `visuals`
- `projects`
- `articles`
- `notes`
- `profile`

每个集合使用明确的数据字段和校验规则。页面从集合读取内容并生成导航、筛选、详情和归档，不把当前工作流数量写死在页面组件中。

交互采用原生 CSS 和少量客户端 JavaScript。首屏工作流场优先使用轻量 Canvas；如性能测试不达标，则退化为预渲染循环媒体与静态备用图。不引入后台数据库。

GitHub Actions 在主分支更新后构建静态文件并发布到 GitHub Pages。第一版使用公开仓库和免费 `github.io` 地址，未来可绑定自有域名。

## 7. 数据流与更新方式

更新流程：

1. 作者提供压缩前图片和文字素材
2. 维护者优化图片、补充结构化字段并添加内容文件
3. 本地预览并校验链接、图片和排版
4. 提交到 GitHub
5. GitHub Actions 自动构建与发布

第一版由维护者协助更新。若内容更新频率明显提高，再评估轻量后台；后台不属于当前范围，但会沿用现有内容字段。

## 8. 性能、错误与降级

- 图片生成多种尺寸，优先使用现代格式，并保留兼容回退
- 首屏不加载完整 60 张作品
- 图片加载失败时显示中性色占位和替代文字
- 未知分类退回“全部”，无结果时显示简短说明
- 无效工作流状态在构建时失败，而不是上线后静默出错
- 缺少可选详情的内容仍可作为普通卡片展示
- 所有详情页提供返回列表和上一篇/下一篇路径
- 提供定制 404 页面
- 动画初始化失败不影响导航、阅读和联系

## 9. 无障碍与隐私

- 键盘可以完成导航、筛选、灯箱关闭和主要链接操作
- 图片提供与用途相符的替代文字
- 正文、按钮和小字号元数据满足基本对比度要求
- 焦点状态清晰可见
- 不自动播放有声音的媒体
- 不接入分析脚本或追踪 Cookie
- 微信二维码旁同时提供邮箱，避免单一联系方式

## 10. 测试与验收

至少验证：

- 桌面、平板和主流手机宽度下的关键页面
- 首页所有导航与锚点
- 工作流新增、排序、重点、归档和版本关系
- 作品分类、灯箱、详情和 60 张以上内容量
- 文章与短灵感的有内容/无内容状态
- 图片懒加载、缺图和慢网状态
- 键盘操作与减少动态效果模式
- GitHub Pages 子路径和未来自定义域名路径
- 构建成功、无失效链接、无明显控制台错误

第一版成功标准：访客可在 1 至 2 分钟内理解作者的 AI 工作流能力和视觉基础，能深入查看代表项目，并能顺利找到微信或邮箱。

## 11. 上线素材清单

开发骨架可先使用占位内容，但正式上线至少需要：

- 个人品牌名或暂用显示名
- 一句身份定位和一句当前状态
- 工作流首批内容、截图和排序
- 60 张左右作品及分类、年份和简短说明
- 代表项目清单
- 一篇文章和 3 至 5 条短灵感
- 筛选后的个人经历和核心工具
- 微信二维码和邮箱

## 12. 后续版本候选

仅在真实需求出现后考虑：

- 内容管理后台
- 完整中英文切换
- 自定义域名
- 基础访问统计
- 更多工作流版本可视化
