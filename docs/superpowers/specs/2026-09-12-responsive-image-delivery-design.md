# 响应式图片加载优化

## 目标

降低手机端首次浏览个人作品集时的图片下载量，同时保留桌面端作品图的清晰度。页面结构、排版、文案和现有图片顺序不变。

## 现状

- 首页共有 32 张图片；完整资源约 6.6MB。
- 图片大多只有一个桌面尺寸版本，手机也会下载同一张大图。
- 形象照为 1.6MB PNG，是单张最大资源。
- 页面已有 `loading="lazy"`，但没有 `srcset` 或 `sizes`。

## 方案

1. 为站内展示的 PNG/JPG 生成 WebP 派生图：640px、1024px、1600px 三档，原文件保留。
2. 形象照生成 640px 与 1024px 两档 WebP，并以 1024px 为桌面上限。
3. 新增一个图片路径辅助模块，统一生成带 GitHub Pages `base` 路径的 `src`、`srcset` 与 `sizes`。
4. 作品卡片、传统作品、首页精选、培训现场、工作流案例及形象照切换到响应式 `<img>` 输出；非首屏图片继续延迟加载。
5. 对图片生成逻辑编写单元测试：必须输出正确的 GitHub Pages 路径，且移动端候选图不超过 640px。

## 不在本次范围

- 不接入第三方图片 CDN。
- 不删除或覆盖原始作品图。
- 不调整网站视觉设计、内容筛选或卡片顺序。
- 不改变二维码文件，以避免影响扫码可靠性。

## 验收标准

- 手机宽度下，首页图片候选资源使用 640px 版本。
- 桌面宽度下，图片可选择 1024px 或 1600px 版本。
- 形象照明显小于现有 1.6MB 文件，同时保持正常观感。
- `npm run check`、`npm run build` 通过；部署后首页和图片链接返回正常。
